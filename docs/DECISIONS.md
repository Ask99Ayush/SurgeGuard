# Decisions made during the build

Each entry records an ambiguity or conflict, the option chosen, and why. Architecture decisions
fixed by the brief (section 2) are not repeated here.

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Design reference | A Raycast screenshot was used as a design-language reference only (no Raycast assets or branding are used). It is not kept in the repository; `docs/design/` is git-ignored. | Avoid committing third-party screenshots. |
| 2 | Next.js version | Next.js **15.5** (not 16). | 16 renames `middleware` and changes defaults; 15.5 is a stable, well-understood App Router release. Pinned exactly. |
| 3 | Where the waiting room is served | Nginx on the protected port proxies `/waiting-room`, `/_next/*` and `/api/v1/queue/*` to SurgeGuard; everything else is the protected origin. The console (landing + admin) is served by the frontend on its own port. | Waiting-room cookies must be same-origin with the protected site. **Constraint:** the protected origin must not use those three path prefixes. |
| 4 | Unprotected comparison path | A second Nginx server (`DIRECT_PORT`) proxying to the *same* backends with no queue, auth or rate limit, bound to loopback. | Keeps the before/after comparison fair (same proxy, same backends, same retries). Local testing only. |
| 5 | Origin lockdown | Network isolation (origins only on an `internal` network) **plus** a shared `X-Origin-Key` header Nginx injects and the origin checks in constant time. | Defence in depth; also makes "direct-origin bypass" testable from inside the network. |
| 6 | `/internal/auth` trust | Nginx sends `X-SG-Proxy-Secret` (overwriting any client value); the API compares in constant time and returns 403 otherwise. Nginx returns 404 for `/internal/*` publicly. | "Only trusted proxy traffic can call it." |
| 7 | Rejoin grace window | A visitor expired **by heartbeat** who rejoins within `REJOIN_GRACE_SECONDS` (default 60) keeps their original sequence number (their place). After the window, or after a token expiry, they go to the back. | Closed laptop lids and throttled background tabs should not cost people their place; abandonment still clears positions after `HEARTBEAT_TIMEOUT_SECONDS`. Tested in `test_queue.py`. |
| 8 | Rejected visitors | `rejected` is terminal for that visitor id until the record expires (`VISITOR_RECORD_TTL_SECONDS`). Rejecting an admitted visitor revokes their token (Redis marker with TTL = remaining lifetime). | Admin action must stick; the revocation must not outlive the token. |
| 9 | Admission rate enforcement | Token bucket stored in Redis and updated inside `admit.lua`, which also re-checks leader-lock ownership (fencing). | A lock alone is not enough (brief); the rate survives restarts and leader changes. |
| 10 | Concurrency cap | `MAX_ACTIVE_ADMITTED` exists but defaults to 0 (off). | Tokens are reusable for their TTL, so "active" means "holds a valid token", not "is browsing"; a default cap would throttle the demo for minutes. The rate is the primary control. |
| 11 | Adaptive admission | Only one rule: rate × healthy/total backends; 0 healthy → auto-pause. Health uses hysteresis (2 failures down, 2 successes up). No latency-based adaptation. | Brief: add adaptive admission only with defined signals/thresholds/cooldowns. This one is defined and tested; latency-based control is not implemented. |
| 12 | Wait estimate | Only from admissions measured in the last `WAIT_ESTIMATE_WINDOW_SECONDS`; fewer than `WAIT_ESTIMATE_MIN_SAMPLES` → "estimate unavailable". Paused → no estimate. | Never derive a number from the configured rate. |
| 13 | Rate limiting | Three layers: Nginx per-IP on all public routes (generous, sized so a single-host k6 run fits), a tighter Nginx per-IP limit on `POST /api/v1/queue/join`, and an app-level per-IP join limit in Redis. | IP is a rate signal only (shared college NAT). Join creates state, so it gets the tightest budget. |
| 14 | Passive vs active health | Nginx: passive (`max_fails`/`fail_timeout`) plus `resolve` (Nginx ≥ 1.27.3) so a stopped container doesn't break startup. Active checks run in the admission worker and drive the admission policy and dashboard, not Nginx routing. | Nginx OSS has no active health checks; we don't pretend otherwise. |
| 15 | Relative redirects | `absolute_redirect off` in the protected server. | Found during e2e: with a remapped host port (or an ALB) absolute redirects pointed at the container port. |
| 16 | Admin password hashing | bcrypt (cost 12) via `bcryptjs` in Next.js; generated by `setup.sh` using Python `bcrypt` locally or in a throwaway container. Stored single-quoted in `.env` so Compose does not interpolate `$`. | Pure-JS verification, no native build. |
| 17 | Login rate limit | In-memory per-client limiter in the Next.js route handler. | Single frontend instance in Compose. Multi-instance deployments need a shared store (documented limitation). |
| 18 | Redis auth | `REDIS_PASSWORD` generated by setup; Redis reads it from a tmp config file so it never appears in the process list. `maxmemory-policy noeviction`. | Eviction would silently corrupt queue state; better to fail (closed) loudly. |
| 19 | Prometheus targets | Compose service names in `prometheus.yml`. | They are topology defined in this repo, not environment-specific values. |
| 20 | Local port clash | On the build machine, port 8080 was already used by another project's container, so the local `.env` uses `PROTECTED_PORT=8088`. `.env.example` keeps 8080. | Do not touch unrelated workloads. |
| 21 | Test Compose project | `make test-backend` always passes `-p surgeguard-test`. | `COMPOSE_PROJECT_NAME` in `.env` overrides the file's `name:`; without `-p`, test teardown (`down -v`) targeted the main stack. Found and fixed during the build. |
| 22 | AWS topology | One host per environment (ASG for self-healing) running the same Compose stack; ALB in front; runtime config from SSM Parameter Store; Session Manager instead of SSH. More than one host requires a shared Redis (not created here). | Each host would otherwise have its own queue. ElastiCache is planned, not implemented. |
| 24 | Demo login | Public credentials (`DEMO_*`) with a one-click button; role set by `DEMO_ROLE` (`admin` = full permissions, `viewer` = read-only, enforced server-side). Default changed to `admin` on request. Allowed only in development/test. | Requested so the console can be fully operated in demos without sharing the personal admin password. Risk: a public full-access login; mitigated by dev-only gating and loopback binding. |
| 25 | Reviewer login | A second full-permission (`admin` role) login, `reviewer`, with a generated password kept in plain text in `.env`, development/test only, never shown in the UI. | Requested for reviewers. Plain text because it is meant to be shared; hashing would only force a second copy elsewhere. The personal admin password stays bcrypt-hashed. |
| 23 | Demo origin metrics label | Demo metrics use an `origin` label instead of `instance`. | Avoids colliding with Prometheus' target `instance` label. |
