# Security

SurgeGuard is a traffic-management layer. It is **not** DDoS protection and does not guarantee zero
downtime: large malicious floods must be absorbed upstream (CDN / provider DDoS protection).

## Trust boundaries

| Boundary | Control | Verified by |
|---|---|---|
| Visitor → origin | Signed JWT checked by Nginx `auth_request` on every request; no token → waiting room | `proxy/tests` (garbage, bad signature, expired, wrong audience, unknown kid, `alg=none`, tampered, other visitor's token, revoked) |
| Client-supplied headers | Nginx overwrites `X-SG-Proxy-Secret`, `X-Origin-Key`, `X-SG-Visitor`, `X-Admin-Key`, `X-Real-IP`, `X-Forwarded-For` | `test_client_supplied_internal_headers_do_not_bypass_auth` |
| Nginx → `/internal/auth` | Shared secret header, constant-time compare; path 404 publicly; API not published | `test_internal_*` (proxy + backend) |
| Anyone → origin | Origins only on an internal network **and** require `X-Origin-Key` (constant-time) | `test_direct_origin_access_is_blocked` |
| Console → admin API | `X-Admin-Key` (constant-time), only from server-side route handlers; allowlisted paths; admin API 404 on the public proxy | `test_admin_routes_reject_missing_or_wrong_key`, proxy isolation tests |
| Operator → console | Roles `admin` / `viewer` (read-only demo, 403 on actions); bcrypt password, signed HttpOnly SameSite=Lax session (HS256, `iss`/`aud`/`exp`), middleware on all admin routes, session re-checked in route handlers, same-origin check on POST, login rate limit | `lib.test.ts`, `LoginForm.test.tsx`, Playwright `admin.spec.ts` |

## Reviewer account (full permissions)

`REVIEWER_LOGIN_ENABLED=true` adds a `reviewer` login with the **admin** role (pause, resume,
reject). Its password is a random value generated by `setup.sh` into the git-ignored `.env`, stored
in plain text so it can be shared with reviewers (compared in constant time, min. 12 characters).
It is not displayed anywhere in the UI, and, like the demo account, it is refused outside
development/test. Rotate by editing `REVIEWER_PASSWORD` and restarting the frontend; disable with
`REVIEWER_LOGIN_ENABLED=false`.

## Demo account

`DEMO_LOGIN_ENABLED=true` adds a login whose credentials are public (`demo` / `surgeguard-demo` by
default, printed on the login page with a one-click button). `DEMO_ROLE` sets its permissions:

- `admin` (current default in `.env.example`): **full permissions**. Anyone who can open the console
  can pause admission and reject visitors. Acceptable only because the console binds to loopback and
  the flag is refused outside development/test;
- `viewer`: every page and read-only API call works, and every state-changing call (pause, resume,
  reject) is refused **server-side** with 403 `read_only` (`requireAdmin()`), not just hidden in the UI;
- the frontend and `validate-config.sh` refuse to start / pass with it enabled outside development/test;
- sessions without a valid `role` claim are rejected.

Disable it (`DEMO_LOGIN_ENABLED=false`), or at least set `DEMO_ROLE=viewer`, before exposing the
console beyond your own machine.

## Failure policy: fail closed

- Redis unreachable → `/internal/auth` returns 503 → Nginx serves the fail-closed page (503) even to
  visitors holding a valid-looking token; joins return 503; the worker admits nobody.
- API unreachable → `auth_request` fails → fail-closed page.
- Verified against the live stack by `scripts/fail-closed-check.sh` and in `backend/tests/test_fail_closed.py`.

## Tokens and cookies

- JWT HS256 with `kid`; required claims `iss aud sub jti iat exp`; algorithm pinned; unknown `kid` rejected.
- `sub` must equal the visitor id from the separately signed `sg_vid` cookie (a copied token alone is not enough).
- Revocation: Redis marker per `jti` with TTL equal to the remaining token lifetime.
- Cookies: `HttpOnly`, `SameSite=Lax`, `Secure` from `COOKIE_SECURE`.
- Rotation: `scripts/rotate-token-key.sh` moves the active key to `TOKEN_VERIFY_KEYS`; drop it after one TTL.

## Secrets

- Only templates (`.env.example`, `infra/terraform/.env.example`, `*.example`) are meant to be tracked. `.gitignore` excludes real env files, tfvars, state, `.terraform/`, keys and build output.
- Secrets are generated locally by `setup.sh`; none are baked into images (all read at runtime).
- Logs: JSON with keys matching secret/password/token/cookie/authorization/api-key redacted and JWT-shaped strings masked; Nginx logs `$uri` (no query strings, no headers).
- No `NEXT_PUBLIC_*` values are used; admin key, session secret and password hash stay server-side.
- CI runs Gitleaks, `pip-audit`, `npm audit` and Trivy.

## Hardening in Compose

Non-root users in every image, `no-new-privileges`, `cap_drop: ALL` where possible, read-only root
filesystems for API, worker, origins and frontend, resource limits, internal networks for Redis and
origins, loopback-only published ports, Redis `requirepass` (not on the command line) and
`noeviction`.

## Known limitations

- The console login limiter is in memory (one frontend instance).
- HS256 means the API holds the signing key; asymmetric keys (planned) would let other services verify without being able to mint.
- The unprotected comparison port exists only for local testing and must not be deployed.
- Grafana and Prometheus have no TLS locally; they bind to loopback.
- Terraform state may contain sensitive resource attributes; use the encrypted backend in `backend.tf.example`.
