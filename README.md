# SurgeGuard

### Survive the surge. Keep every user in line.

**A self-hosted virtual waiting room that protects a fragile website from sudden traffic spikes with fair, first-come-first-served admission.**

Built for InnoTech '26 · Smart Solutions, Smarter Society

</div>

---

SurgeGuard sits in front of a site that struggles under bursts of traffic (exam results, fee portals,
ticket sales). Visitors without an admission token are sent to a waiting room; a worker admits them in
order at a configurable rate; Nginx lets only admitted visitors reach the origin. If SurgeGuard cannot
verify admission (Redis or the API down), it **fails closed** — nobody is sent to the origin.

It is not a DDoS shield and does not make a slow origin faster. It keeps the load the origin sees within
what it can serve, and tells waiting visitors their real position.

## What's in the box

| Part | Path | Implemented |
|---|---|---|
| Queue API (FastAPI, Python 3.12) | `backend/app/api` | join/status, `/internal/auth`, admin API, `/healthz` `/readyz` `/metrics` |
| Redis queue (Lua scripts) | `backend/app/repositories` | INCR-sequenced ZSET, idempotent joins, heartbeat expiry, grace-window rejoin, revocation |
| Admission worker | `backend/app/workers` | fenced leader lock, Redis token bucket, health-aware rate, auto-pause |
| Edge proxy (Nginx 1.28 OSS) | `proxy/nginx` | `auth_request`, fail-closed pages, per-IP rate limits, static-only cache, bounded retries, passive health |
| Fragile demo origin | `demo-site` | concurrency limit + simulated slow work, two instances, origin key |
| Console + waiting room (Next.js 15, Tailwind, Recharts) | `frontend` | landing, waiting room, login, dashboard, queue, backends, monitoring, settings |
| Monitoring | `monitoring` | Prometheus scrape + 9 alert rules, 5 provisioned Grafana dashboards |
| Load tests (k6) | `loadtest` | surge (identical profile both ways), backend failure, fairness, side-by-side summary |
| AWS (Terraform) | `infra/terraform` | VPC, ALB, ASG host, SSM config, IAM — validated offline only, never applied |
| CI | `.github/workflows` | lint, types, tests, Docker build, integration + proxy tests, Terraform validate, Gitleaks, dependency + image scans |

## Quick start

Requirements: Docker with Compose v2, bash (Git Bash on Windows), GNU make, Node 22 (for frontend tests).

```bash
make setup    # generates .env with fresh secrets; prints the admin + Grafana passwords once
make up       # builds and starts everything, waits until healthy
make demo     # 5-minute before/after demo with a side-by-side summary
```

| URL (defaults) | What |
|---|---|
| http://localhost:8080 | The demo site **protected** by SurgeGuard (you'll pass through the waiting room) |
| http://localhost:8081 | The same site **unprotected** (local comparison only) |
| http://localhost:3000 | Landing page and operator console (`/login`) |
| http://localhost:3001 | Grafana |
| http://localhost:9090 | Prometheus |

Ports come from `.env` (`PROTECTED_PORT`, `DIRECT_PORT`, …) and bind to loopback.

**Demo login:** on `/login`, click **Use demo account** (`demo` / `surgeguard-demo`). With the default
`DEMO_ROLE=admin` it has **full permissions** (pause/resume admission, reject visitors); set
`DEMO_ROLE=viewer` to make it read-only. Development only; turn it off with `DEMO_LOGIN_ENABLED=false`.

**Reviewer login (full permissions):** user `reviewer`, password = `REVIEWER_PASSWORD` in your `.env`
(generated by `make setup`). Share it with reviewers; it can pause/resume admission and reject
visitors. Development only; turn it off with `REVIEWER_LOGIN_ENABLED=false`.

## Commands

| | |
|---|---|
| `make test` | backend (ruff, mypy, pytest on a throwaway real Redis) + frontend (Vitest) |
| `make test-proxy` | proxy/security-boundary tests against the running stack |
| `bash scripts/fail-closed-check.sh` | stops Redis, then the API, and verifies admitted visitors are refused |
| `make e2e` | Playwright (set `SITE_URL`, and `E2E_ADMIN_PASSWORD` for admin flows) |
| `make lint` | ruff, mypy, eslint, tsc, shell syntax |
| `make loadtest` / `make demo` | k6 comparisons (see `loadtest/README.md`) |
| `make terraform-validate` | offline `fmt -check` + `validate` |
| `scripts/rotate-token-key.sh` | rotate the token signing key without logging visitors out |
| `scripts/setup.sh --reset-admin-password` | new admin password |

## Limitations

- Single Redis; one host in the AWS layout (more hosts need a shared Redis, planned).
- Adaptive admission only reacts to backend health checks (not latency).
- Console login rate limiting is per frontend instance.
- Visitors still wait during a surge; the estimate is shown only when it can be measured.
