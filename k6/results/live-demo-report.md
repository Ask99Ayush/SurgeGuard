## How to Run

```bash
# Single simultaneous demonstration command (using real public domains):
k6 run \
  --ca-cert certs/surgeguard.crt \
  k6/scripts/live-demo.js

# With custom VU counts and hold duration:
k6 run \
  --ca-cert certs/surgeguard.crt \
  -e UNGUARDED_VUS=20 \
  -e GUARDED_VUS=20 \
  -e HOLD=60s \
  k6/scripts/live-demo.js

# Using Docker Compose (recommended on EC2):
docker compose --profile loadtest run --rm k6 \
  run \
  -e UNGUARDED_VUS=20 \
  -e GUARDED_VUS=20 \
  scripts/live-demo.js

# Targeting internal container network (for local Docker testing):
k6 run \
  --ca-cert certs/surgeguard.crt \
  -e GUARDED_URL=https://nginx:8443 \
  -e UNGUARDED_URL=http://nginx:8081 \
  -e INSECURE_TLS=true \
  k6/scripts/live-demo.js
```

## Limitations

- The unguarded demo origin uses an asyncio semaphore with `DEMO_MAX_CONCURRENCY` slots (default: 8).
  503s are genuine — not fabricated — but they require sufficient concurrent VUs to trigger.
- If `DEMO_MAX_CONCURRENCY` is set high or `DEMO_WORK_MS` is low, fewer 503s may appear.
- Queue wait times depend on `ADMISSION_RATE` and the number of queued visitors.
- TLS certificate verification uses the self-signed cert at `certs/surgeguard.crt`.
